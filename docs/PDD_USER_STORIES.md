# PDD user-story catalog

This catalog connects product value to each generation prompt. The user story says why the module exists; the prompt's stable `R<n>` rules are its executable acceptance criteria; the contract-test column identifies where those criteria are proved.

Do not restate individual prompt rules here. The prompt remains the behavioral authority, while this catalog provides traceability and a product-level review surface. `authored` means the contract-test file exists and names every rule. It does not mean generated implementation tests are currently unskipped. `planned` means the prompt has a proposed test path that still needs to be authored.

Run `npm run pdd:stories` for the normal catalog check. Run `npm run pdd:stories -- --strict` when accepting a phase; strict mode rejects every planned test suite.

## Story review gate

A reviewer accepts a story only when:

1. the persona and value statement agree with the product scope;
2. the prompt has exactly one responsibility and does not absorb product ambiguity;
3. every prompt rule in the declared range is observable in the named contract suite;
4. negative, unknown, conflict, and failure behavior is tested where relevant;
5. the generated implementation passes without skipped tests before its evidence manifest is accepted; and
6. at least one integration or end-to-end journey proves the story when it crosses module boundaries.
